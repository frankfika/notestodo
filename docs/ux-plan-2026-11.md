# openNotion 整体 UX 优化规划

> 2026-11-09。基于用户反馈：「任务好乱」「拖拽不丝滑」「会议记录完全无效不可用」「我都不知道干嘛的」。
> 核心判断：**功能不缺，缺的是「开箱即用」和「一致性」。** 每个页面单看都能用，连起来不像一个产品。

## 现状诊断（四大症结）

1. **功能不可发现** — 双击改名、⋯ 菜单里的日期/标签、拖拽成子任务，全靠用户自己悟。没有空状态引导、没有快捷键提示、没有「这是什么」的即时答案。
2. **破坏性操作不友好** — 全仓 11 处 `window.confirm`，删了就没了，没有撤销。
3. **首次体验门槛高** — 会议功能 = 录音权限 + 屏录权限 + 下载 ASR 模型 + 下载 LLM 模型，任何一步卡住都「完全不可用」（用户原话）。而这恰恰是产品的主打功能。
4. **交互语言不统一** — 有的双击编辑、有的单击；有的删除弹 confirm、有的直接删；拖拽只在一处存在。

## 已交付

### 任务页
- 单击标题即改 / 新建即聚焦 / 删除可撤销（toast）/ 行内 ＋ 快捷操作
- 拖拽：⠿ 手柄 + 蓝色插入线（同级排序 + 挂子任务）+ 悬停自动展开 + 折叠父级自动展开
- 层级：24px 缩进 + 连续引导线（Notion 大纲样式）
- 默认视图改为按时间分组列表；头部三栏并一栏；来源 chip 降噪为 hover 才显示
- 触屏设备：hover 才出现的按钮常驻（`hover-only` + `@media (hover:none)`），否则手机上根本点不到 ⋯ 菜单

### 任务页键盘流
- `↑`/`↓` 在行间移动（roving tabindex，Tab 只进一次列表）
- `Enter` 进编辑 / `Space` 勾选完成 / `⌫` 删除（带撤销）
- 编辑中 `Enter` 保存并新建同级（飞书连打）/ `Esc` 取消（新建空任务直接丢弃，不留「（无标题）」空壳）
- 编辑中 `Tab` 缩进成上一个同级的子任务 / `Shift+Tab` 提升一级（层级操作不必再拖拽）
- 删行后焦点自动落到下一行

### 破坏性操作全部可撤销（原 11 处 `window.confirm` 已清零）
- 看板 / 列 / 模板 / 笔记 / 会议 / 会议对话 / 标签：先执行 + toast「已删除」+ 撤销
- 级联删除（删会议 → 转录/纪要/待办）先整场快照，撤销时原样写回
- 删标签会连带解绑 N 处引用，撤销后引用计数回到删除前
- 导入（覆盖型）无法靠软删撤销 → 改为**导入前快照 + 失败自动回滚 + 成功后给撤销窗口**

### 「今天」落地页
- 应用打开不再甩一个空 AI 输入框，而是今天要做的任务 + 正在录的会 + 最近的会议
- 快速添加默认今天到期，支持自然语言（「明天 交方案 @张三」）
- 空状态给「这是什么 + 第一步做什么 + 两个行动按钮」

### 会议录音可诊断（P0）
用户原话「外部声音根本录不进去，模型也不好」——根因是**全程没有反馈**，不是单一 bug。已补三处当场诊断：
- **0 电平告警**：连续 3 秒没检测到声音 → 提示麦克风静音/未授权/外放，给「检查麦克风」直达系统设置（新增 Rust 命令 `open_microphone_settings`）
- **系统声音 0 chunk 告警**：声称在录系统声音却一个 chunk 都没收到 → 明说「对方的声音不会进这段录音」
- **模型未下载提示**：录音当下就说「录完会等它」，并给「下载 0.6GB」与「先下轻量版 0.2GB」二选一 —— 不阻断录音，但不再等录完一小时才发现
- 已有能力保留：屏幕录制授权向导（自动弹出 + 一键授权 + 打开设置 + 重启生效）、会议页「等待模型」卡片 + 一键下载 + 模型下好自动续跑

### 其他
- 全局快捷键速查卡（`?` 唤出，Esc 关闭，macOS 显示 ⌘ / 其他 ⌃）
- 记住上次所在页面（sessionStorage：刷新回原地，重开应用仍从「今天」开始）

## 未做（及原因）

| 项 | 原因 |
|---|---|
| 拖拽跨视图（大纲 → 看板列） | 看板和任务树是两个互斥路由，跨视图拖拽需要同时渲染两个页面 —— 是功能级改造，不是打磨。收益中等、成本高 |
| 移动端左右滑动手势 | 手势不可发现；触屏上「⋯ 菜单 / ＋ 子任务 / 完成」已改为常驻按钮，覆盖了移动端的核心诉求 |
| 笔记 → 任务反向链接 | 已存在（笔记详情有「关联任务」section） |
| 看板列间拖拽 | 已存在 |
| 任务三视图状态同步 | 已自动生效（三视图都读 Dexie liveQuery，列表勾掉 → 看板同步进已完成列） |

## 遗留建议（下一轮）

1. **系统音频真机验证**：以上诊断逻辑只能证明「我们能告诉你没录到」，不能保证「一定录得到」。macOS 上 ScreenCaptureKit 抓显示器音频有三个已知限制：对方声音必须从该显示器出声、多显示器时声音在别的屏上抓不到、dev 未签名构建每次重编译授权都会失效。建议用打包后的 .app 在真实 Zoom 会议里验证一轮。
2. **首次录音的引导顺序**：现在是「点录音 → 弹授权向导」。可考虑在第一次打开应用时就先问「要不要录系统声音」，把授权前置到录音之前。
3. **P0-4 大模型二选一**：目前只在录音条上给了「先下轻量版」；设置页的模型选择面板也该有同样的权衡说明（体积 / 速度 / 质量）。
