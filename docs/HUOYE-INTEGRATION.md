## 1. 合并的真实形态（先说结论）

这次合并是**「同仓共置」**，不是把两套 UI 融成一套，也**没有交付数据桥**。准确地说：

| 层面 | 状态 | 说明 |
|---|---|---|
| notestodo 原有应用（`web/`） | **原样保留，未改一行** | 会议速记 / Notion 式页面树 / 任务四视图 / 块评论 / MCP / relay 全部照旧运行 |
| 活页应用（`huoye/`） | **整体迁入，源码、字体、测试、文档齐全** | 独立的 pnpm monorepo：Hono 本地 API + Electron + React，Today 式界面 |
| 数据桥（`integration/`） | **不存在，未交付** | 仓库根目录没有 `integration/` 目录；曾有「数据桥已随合并交付」的说法，不准确，已纠正 |
| 单一 UI 融合 | **未做** | 目前是两个可分别运行的 App 共用一个仓库，内容不会自动互通 |
| 实时同步 | **未做** | 连显式导入/导出桥都还没有，更没有后台同步 |

也就是说：**不是「活页取代 notestodo」，也不是「两个 App 扔进一个目录就算完」**——
原有 notestodo 一个字节没动，新能力是加法；但两边内容目前**没有自动互通的通路**，
只有活页的「本地文件夹连接器」可以挂接用户自己指定的目录（见第 4 节）。

## 3. 活页带来了什么

活页不是「另一个记事本」，它是一套**以对话为主、记忆可检查**的个人助手：
今天页是家，对话框是主沟通方式，记忆是可检查的 Markdown，先确认再行动。

- **今天页**：今天要做的事、会、日程一屏摊开，而不是一个空的 AI 输入框。
- **对话优先**：建任务、改任务、完成、整理会议、写一页笔记，都从对话框发起。
- **一等公民的笔记**：记忆文件本身就是笔记，空页即可写、标题自动聚焦。
- **会议**：录音 → 转录（BYOK）→ 一次整理出标题/纪要/待办，纪要落 Markdown，待办带出处。
- **主动外联（proactive）**：定时生成简报与提醒，**默认关闭**，需要用户显式开启。
- **可检查的记忆**：`$HUOYE_HOME/memory` 下是纯 Markdown + YAML 头，可 grep、可 diff、可进 git。

界面沿用 Today 气质，字体用 OFL 授权的 Figtree Variable / Noto Sans SC（经 `@fontsource` 引入）。

## 4. 数据桥：当前真实状态（尚未交付）

先说清楚：**仓库里没有 `integration/` 目录，自动导入/导出数据桥没有交付。**
合并前的交接说明曾声称它已随 PR #56 合入（双向转换 + CLI + 单测），实际并不存在；
「数据桥已存在」的说法不准确，本文档按 2026-11-25 复核结果纠正。

目前两边的真实关系只有这些：

- **共置**：两个可独立运行的 App 在同一个仓库，各自的 pnpm 工作区、各自的存储，互不干扰。
- **活页的本地文件夹连接器**：在活页「设置 → 连接器」里可以挂接**你自己指定**的本地目录，
  查看其顶层内容（不会顺着外部符号链接走，也不会上传云端）。这是**用户显式挂接目录**，
  不是自动数据桥：它不会把 notestodo 的笔记/会议自动转成活页记忆，也不会反向导出。
- **两个存储各有各的真相**：活页用 Markdown 文件记忆，notestodo 用 IndexedDB。
  自动导入/导出桥、后台同步、冲突合并**都没做**，列在下方「没做」一节和下版计划里。

## 5. 明确保留 / 明确没做

**保留**：notestodo 的全部历史与功能（`git log` 未改写，v0.7.0 全部文件原样）、
notestodo 的 MIT License 与全部文档、活页自己的 MIT License。

**没做（且如实写在这里）**：

- **没有数据桥**：`integration/` 目录不存在，自动导入/导出桥未交付；后台自动同步与冲突合并更无从谈起。
- 没有把两套 UI 融成一套；今天页 / 侧栏树 / 块编辑器目前并存于两个 App。
- 主动外联（proactive）在本仓库里**默认关闭**，没有在任何既有工作区上擅自开启。
- 渠道（飞书 / 钉钉 / 企微 / 微信）**尚未真机联调**，需要真实凭据与真实回调地址；真实设备推送**未验证**。
- 部分模型调用尚未在真实账号上跑通（转录与整理的端到端效果待真机验证）。
- token 收费中转未做——产品定位明确**不做订阅墙**（开源免费、BYOK）。
- CI 的「前端构建 + e2e」job 在合并前失败，原因正在排查，**尚未修复**。
- 本次合并**未发布** GitHub Release，也**未打 tag**。

## 6. 怎么跑起来

```bash
# 原来的 notestodo
cd web && pnpm install && pnpm dev

# 活页
cd huoye && pnpm install && pnpm dev
```

两套 App 各自独立运行，互不抢端口（活页默认与 notestodo 不共用进程）。
没有数据桥可跑——两边的内容目前只能各看各的，或手动复制文件。
